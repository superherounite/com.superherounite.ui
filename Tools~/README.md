# Package validation tools

English | [한국어](README.ko.md)

[`Validate-Package.ps1`](Validate-Package.ps1) prepares an isolated Unity host
from [`TestProject~`](../TestProject~) and runs the official EditMode Test Runner.
It discovers the package's Editor tests, including the host's callback
regressions. Optional modes select the larger mixed workload or comparison
with the original processor.

The commands below are usage examples, not recorded validation results. Run
them from the package repository root with PowerShell 7 or newer and an
installed, usable Unity `6000.0.68f1` Editor.

## Editor test suite

```powershell
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath 'C:/Program Files/Unity/Hub/Editor/6000.0.68f1/Editor/Unity.exe'
```

`Tests` is the default mode. It runs the `SuperHeroUnite.UI.Editor.Tests`
assembly with `Scale` and `PerformanceComparison` categories excluded. Ordinary
scaling regressions remain included. It does not use the deprecated
`StyleRecipeProcessorBatchRunner.Run`, which runs only the original 12 smoke
tests.

By default, Unity runs with `-batchmode -nographics`. Tests tagged
`EditorGraphics` that exercise Inspector-window creation are recorded as
ignored when Unity reports no graphics device. A passing headless run therefore
does not verify that window-opening action. To include it on a machine with a
usable graphics device, enable graphics explicitly:

```powershell
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath 'C:/Program Files/Unity/Hub/Editor/6000.0.68f1/Editor/Unity.exe' -EnableGraphics
```

`-EnableGraphics` omits `-nographics` from both Editor invocations while keeping
batch mode and hidden process windows. If Unity still reports a null graphics
device, the graphics test remains ignored; check the NUnit XML for skipped
tests. This action test does not replace visual inspection of the Inspector.

The host references the current checkout through a local `file:` package
dependency and lists `com.superherounite.ui` in `testables`. A separate Editor
invocation resolves packages, compiles the host, and imports **TMP Essential
Resources** if the default font is missing. The bootstrap and Test Runner each
control Editor exit; the script does not add `-quit`, which could terminate
asynchronous work early.

## Optional workloads

| Mode | Owner counts | Default count | Purpose |
| --- | --- | --- | --- |
| `Tests` | Does not filter by owner count | Not applicable | Complete ordinary Editor regression suite |
| `Scale` | `300`, `1000` | `300` | Mixed uGUI/TMP, Variants, runtime-only scripts, and Editor callbacks with shared consumers |
| `Comparison` | `100`, `200`, `300` | `100` | Same-asset baseline comparison with four Image bindings per owner |

```powershell
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath $env:UNITY_EDITOR_PATH -Mode Scale -OwnerCount 300
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath $env:UNITY_EDITOR_PATH -Mode Scale -OwnerCount 1000
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath $env:UNITY_EDITOR_PATH -Mode Comparison -OwnerCount 100
```

For these examples, `UNITY_EDITOR_PATH` must already contain the Editor
executable path. `Scale` checks incremental/full result equality, dependency
propagation, callback fallback, file preservation, and operation counts while
logging elapsed times. It is synthetic rather than a copy of a consuming
project's UI.

`Comparison` copies its harness from `TestProject~/Comparison`, then uses `git
show` at commit `7ede1ed6229c7b03b4d3adfddc42a283d6ef63b0` to generate the legacy
processor and resolver inside the host. Git and that commit must be available
locally. Only class identifiers and their references are renamed. Legacy source
is not kept in the package and is not generated by `Tests` or `Scale`. See the
[performance report](../Documentation~/performance.md) for measurement
conditions and interpretation.

## Parameters and host reuse

| Parameter | Behavior |
| --- | --- |
| `-EditorPath` | Required Editor executable path, including with `-PrepareOnly` |
| `-Mode` | `Tests` by default; also accepts `Scale` and `Comparison` |
| `-OwnerCount` | `0` selects the mode default; supported counts are above; `Tests` does not restrict its suite by this value |
| `-ProjectDirectory` | Optional dedicated host directory outside the package source |
| `-TimeoutSeconds` | Default `1800`, range `60`–`14400`; applies separately to each Editor invocation |
| `-EnableGraphics` | Omits `-nographics` so `EditorGraphics` action tests can run with a usable graphics device; disabled by default |
| `-PrepareOnly` | Writes host files and manifest, then returns the project path without launching Unity or importing TMP resources |

NUnit separately limits each `Scale` test to 10 minutes and each `Comparison`
test to 20 minutes. These limits are independent of `-TimeoutSeconds`, whose
default 30 minutes covers each entire Editor invocation, including startup and
imports. Increasing `-TimeoutSeconds` does not change the NUnit test limits.

By default, each checkout and mode gets a reusable host in the system temporary
directory at `SuperHeroUIValidation/<source-path-hash>/<Mode>`. Reuse retains
`Library` and results. A custom directory must be empty or contain the matching
`.superhero-ui-validation.json` marker for the same package source and mode.
The script rejects an unmarked non-empty directory, a host inside the package
source, and a host already open in Unity. A separate run lock prevents
concurrent scripts from preparing the same host.

Keep changes in the repository's `TestProject~` templates. On reuse, the script
copies current template files and records their relative paths in
`.superhero-ui-template-files.json`. Files removed from the template are removed
from the next host preparation only if previously recorded as managed, along
with their obsolete metadata, within the checked host directories. Imported TMP
resources and `Library` are retained. Choose another empty host directory for a
completely fresh import.

```powershell
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath $env:UNITY_EDITOR_PATH -Mode Scale -OwnerCount 1000 -ProjectDirectory 'C:/Validation/SuperHeroUI-Scale' -TimeoutSeconds 3600
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath $env:UNITY_EDITOR_PATH -Mode Tests -ProjectDirectory 'C:/Validation/SuperHeroUI-Tests' -PrepareOnly
```

The package still has no runtime assembly. Runtime scripts under
`TestProject~/Assets/CallbackProbe` and `TestProject~/Assets/ScaleTests` belong
only to the generated host, where real Prefab callbacks can be exercised. The
tilde-suffixed template folder is not imported as package runtime code.

## Results and CI

The host's `Results` directory receives files named with a UTC timestamp and
unique run suffix:

- `<run>-bootstrap.log`: package, compilation, and TMP setup output;
- `<run>-tests.log`: Editor and Test Runner output;
- `<run>-<Mode>-<OwnerCount>.xml`: NUnit results and fixture output;
- `<run>-summary.json`: mode, host, result, counts, exit code, duration, and
  report/log paths, once a test report exists.

`Comparison` also writes `legacy-vs-current-<OwnerCount>-owners.json` containing
measurements. That file is updated by another comparison at the same owner
count; retain it with the corresponding timestamped reports when preserving
history. Scale timings and operation counts appear in test output and XML.

Unsuccessful Unity exit, timeout, missing test report, reported failures, zero
selected tests, or zero passing tests make the script fail. Setup or compilation
failure can stop before XML and summary JSON exist; use the bootstrap log.
The script's process timeout terminates only the Editor it started and its
children. `-PrepareOnly` prepares files and does not report a test result.

An existing CI job with PowerShell, the Editor, and its required environment can
use the same command and retain the reported results directory:

```powershell
pwsh -NoProfile -File ./Tools~/Validate-Package.ps1 -EditorPath $env:UNITY_EDITOR_PATH -Mode Tests -ProjectDirectory 'C:/Validation/SuperHeroUI-CI'
```

Package validation does not replace a consuming project's visual, interaction,
localization, or Player Build checks.
